# Перехід User Gender Replacer з jsDelivr на npm

Я опублікував свій скрипт у npm, щоб його можна було підключати в курсах Articulate Rise через **LMS Collaborator**. Робочий JavaScript під час перенесення залишив без змін.

- npm: [asimut-user-gender-replacer@1.0.0](https://www.npmjs.com/package/asimut-user-gender-replacer/v/1.0.0)
- GitHub: [Asimut/user_gender_replacer](https://github.com/Asimut/user_gender_replacer)
- Браузерний файл: `selezen_v1.js`

## Як змінюється підключення

Раніше курс завантажував скрипт із jsDelivr. При підключенні через LMS команда Collaborator перевіряє конкретну версію npm-пакета, встановлює її та надає адресу файлу для SCORM. Саме встановлення пакета не робить файл доступним у браузері.

User Variables отримує дані користувача через SCORM API. User Gender Replacer використовує ці дані для заміни тексту з урахуванням статі. Спочатку підключаю User Variables, потім Gender Replacer.

Обидва пакети вже опубліковано. Підключення у SCORM змінюю після підтвердження встановлення в LMS та остаточних адрес файлів.

## Встановлення в LMS

Команда встановлення обох пакетів для команди Collaborator:

```sh
npm install --save-exact --ignore-scripts asimut-user-variables@1.0.0 asimut-user-gender-replacer@1.0.0
```

Файли після встановлення:

```text
node_modules/asimut-user-variables/selezen_v1.js
node_modules/asimut-user-gender-replacer/selezen_v1.js
```

Це шляхи на диску сервера. URL для браузера може відрізнятися — його визначає команда Collaborator. Для підключення потрібен доступ до цих файлів, а не до всього каталогу `node_modules`.

## Заміна посилання у SCORM

Попереднє підключення User Gender Replacer:

```html
<script defer src="https://cdn.jsdelivr.net/gh/asimut/user_gender_replacer/selezen_v1.js"></script>
```

Якщо Collaborator підтвердить доступність обох файлів саме за наведеними нижче адресами, підключаю їх так:

```html
<script defer src="/node_modules/asimut-user-variables/selezen_v1.js"></script>
<script defer src="/node_modules/asimut-user-gender-replacer/selezen_v1.js"></script>
```

Зберігаю порядок підключення, `defer` і поточну конфігурацію `window.GenderReplacer`. Старий тег того самого скрипту прибираю, щоб не запускати його двічі.

Початковий `/` означає корінь origin документа курсу. Якщо SCORM працює в iframe на іншому домені, браузер шукатиме файл саме на цьому домені. Тому адресу перевіряю всередині реального LMS-плеєра. Доступ до SCORM API через батьківське вікно також залежить від політики origin.

Посилання `cdn.jsdelivr.net/npm/...` усе ще веде на jsDelivr і може блокуватися тією самою CSP.

## Перевірка курсу

Спочатку оновлюю копію одного курсу та перевіряю:

- Обидва файли завантажуються з HTTP 200, містять JavaScript і мають належний Content-Type; блокування CSP немає.
- SCORM API повертає потрібні поля. `%user_firstname%`, `%user_email%` та інші використані маркери заповнюються правильно, зокрема за порожніх значень окремих полів.
- Фото завантажується, якщо воно є; його адресу дозволяє `img-src`.
- Gender Replacer отримує дані в тому самому вікні. Зберігаються `targetBlocks` і `genderReplacements`; за явно заданого `female` відбуваються налаштовані заміни, за `male` початковий текст зберігається.
- Працюють переходи між екранами, динамічні блоки й використані iframe та Shadow DOM.
- Зберігаються прогрес і завершення курсу.

Набір доступних полів залежить від LMS. Поточний User Variables виводить отриманий профіль і URL фото в консоль браузера. Gender Replacer використовує евристики, якщо явно заданої статі немає. Перенесення на npm не змінює цієї поведінки.

## Оновлення наявних курсів

Публікація в npm і встановлення пакета в LMS не змінюють HTML усередині старих SCORM-архівів. Після перевірки оновлюю свої курси та шаблони експорту. Компаніям, які використовують скрипти, передаю погоджені адреси підключення; свої курси вони оновлюють за процедурою LMS.

Під час перепакування зберігаю структуру ZIP з `imsmanifest.xml` у корені. Перед оновленням робочого курсу перевіряю збереження прогресу на його копії. Для інших LMS сумісність і адреси підключення уточнюю окремо.

Початкові файли GitHub і посилання jsDelivr залишаю доступними для тих, кому таке підключення досі дозволене.

## Наступні версії

Для змін пакета публікую новий номер версії. Коміт GitHub сам по собі не оновлює npm або встановлену копію в LMS. Команда Collaborator фіксує погоджену версію та контролює її оновлення.

Якщо адреса файлу не змінюється, нова версія впливає на всі підключені курси. Для несумісних змін погоджую окрему адресу; для відкату зберігаю попередню погоджену версію.
